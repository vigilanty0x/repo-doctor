# Operations and release runbook

## Local verification

Run from a clean checkout with Python 3.11 or newer:

```bash
python scripts/check.py
python scripts/release_gate.py
```

The release gate is platform-neutral and forces pip offline. It builds a direct
wheel and sdist, rebuilds a wheel from the sdist, compares their unpacked
contents, installs source/wheel/sdist into separate temporary environments, and
exercises version, plugin catalog, scan, SBOM, and `pip check` from outside the
checkout.

## Release checklist

1. Confirm `pyproject.toml` and `src/repo_doctor_ai/__init__.py` declare the same version.
2. Add dated user-visible notes to `CHANGELOG.md`.
3. Run the full matrix locally where available and in GitHub Actions on Linux and Windows for Python 3.11 and 3.12.
4. Build both wheel and sdist, rebuild a wheel from the sdist, and install both artifacts into clean environments.
5. Run self-audit, synthetic example, all report renderers, baseline/diff/plan workflow, journal replay, and SBOM generation.
6. Review the package contents and SHA-256 digest.
7. Create a signed or protected release tag according to repository policy.

## Rollback

Repo Doctor has no service, remote account, schema migration, or background state. To roll back:

1. reinstall the last trusted wheel;
2. restore the prior CI action or package version;
3. retain reports and journals generated by the failed release for diagnosis;
4. regenerate baselines only if fingerprint semantics intentionally changed.

Reports remain plain artifacts. A 2.0 reader is not required to consume the stable version 1 report fields, but older automation must ignore the new score and suppression fields.

## Incident handling

If a report exposes sensitive content, stop distribution, preserve the artifact securely, determine whether the source matcher violated the redaction invariant, and rotate any potentially exposed credential. Use GitHub private security advisories for product vulnerabilities. Do not attach live repository data to public issues.

If a scan unexpectedly becomes `DEGRADED`, `WAITING`, or `REJECTED`, retain its `reason_code`, metrics, and bounded errors. Correct the root cause before using the result as a release gate.
